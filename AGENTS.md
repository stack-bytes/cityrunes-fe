# Repository notes

- This is a single Expo 57 / Expo Router app (npm lockfile; no workspace). Install with `npm ci`, run with `npm start`; `npm run ios`, `npm run android`, and `npm run web` use the scripts in `package.json`.
- Verification: `npm run lint` (`expo lint`); focus on one file with `npx eslint 'app/(tabs)/MapPage.tsx'`; typecheck with `npx tsc --noEmit`. There is no test script or test suite configured.
- Do **not** run the README's `npm run reset-project`: its target `scripts/reset-project.js` is absent. `scripts/` only holds `seed-auth-users.mjs`, a one-off Node script that creates a Supabase Auth login for every `public.users` row with the same UUID. It needs `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` and `SEED_PASSWORD` in the shell environment; the service-role key must never go into the app, `environment.ts`, or git.
- Never leave comments. Code should be self-explanatory.
- Always verify AGENTS.md after doing anything to see if you need to add or remove anything from here.

## App wiring

- `package.json` enters through `expo-router/entry`. `app/index.tsx` redirects to `/(auth)/Welcome`; its Login button navigates to `/(tabs)/FeedPage` without an auth backend. `app/_layout.tsx` loads Silkscreen fonts and wraps all routes in the Redux provider and gesture-handler root. Inside it, `components/CatalogGate.tsx` dispatches `loadCatalog` on launch and shows a spinner until the first load settles; `components/ConnectionBanner.tsx` renders over the routes.
- `app/(tabs)/_layout.tsx` hides the default tab bar and renders `components/Navbar.tsx`; the navbar explicitly routes to Feed, Map, and Profile even though only Feed is declared in the Tabs layout. Standalone screens such as Camera and Quiz live directly under `app/`.
- Roads, places, and quests are fetched from Supabase at launch with `@supabase/supabase-js` (`lib/supabase.ts`). `actions/catalog.ts` `fetchCatalog` runs three parallel queries (`roads` with `road_places`, `places`, `quests` with `quiz_questions`) with an 8s timeout, and fails on any error or when roads or places come back empty. `utils/catalogMapper.ts` maps snake_case rows to the `Road`/`Place`/`Quest` types: road places are ordered by `position`, a road's quests follow its place order, and a quiz quest uses only its first `quiz_questions` row (sorted by id). The `loadCatalog` thunk in `store/slices/catalogSlice.ts` (`status`, `initialLoadSettled`) is handled by the `roads`, `places`, and `quests` slices. Those slices start from `mocks/`, so a failed load leaves the mock data in place and `ConnectionBanner` shows "Cannot connect to the database" with a Retry button. Quests are read with `selectQuestByPlaceId` from `store/slices/questsSlice.ts`. The anon key needs SELECT policies on `roads`, `places`, `road_places`, `quests`, and `quiz_questions`; without them Supabase returns empty lists and the app falls back to mocks.
- User state in `store/slices/userSlice.ts` still starts from `mocks/user-mock.ts`, and badges in `StorePage` still come from `mocks/mock-store.ts`. The camera flow is different: `actions/camera.ts` posts photos to `/verify-location` using the hard-coded ngrok `apiUrl` in `environment.ts`. Check that endpoint before relying on photo verification.
- The leaderboard is always fetched from the Supabase edge function `get-leaderboard` (`GET ?trackId=<road id>`) by `actions/leaderboard.ts`, through `hooks/useTrackLeaderboard.ts` (React Query; `QueryClientProvider` lives in `app/_layout.tsx`). Config is `supabaseUrl` and `supabasePublishableKey` in `environment.ts`. Points earned in Camera and Quiz are not written back to the backend. `MOCK_USER.id` is the real `raresc4` UUID so the leaderboard can highlight the current user.
- `app/(tabs)/MapPage.tsx` renders `MapView` and `Marker` from `react-native-maps`; do not assume the map works on web. Place, badge, and avatar images are resolved by `resolveImage` in `utils/resolveImage.ts`: `imageUrl` wins, otherwise `imageId` is looked up in its single static `IMAGE_MAP` require table, otherwise the `statuie.png` fallback is used. Add a table entry whenever a new `image_id` appears in the database or mocks.
