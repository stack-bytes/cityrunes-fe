# Repository notes

- This is a single Expo 57 / Expo Router app (npm lockfile; no workspace). Install with `npm ci`, run with `npm start`; `npm run ios`, `npm run android`, and `npm run web` use the scripts in `package.json`.
- Verification: `npm run lint` (`expo lint`); focus on one file with `npx eslint 'app/(tabs)/MapPage.tsx'`; typecheck with `npx tsc --noEmit`. There is no test script or test suite configured. `npm run lint` already reports an error in `Navbar.tsx` and unused-variable warnings in `CameraPage.tsx`. Typed routes live in the generated `.expo/types/router.d.ts`; after adding a route, `tsc` fails on links to it until `npm start` regenerates that file.
- Do **not** run the README's `npm run reset-project`: its target `scripts/reset-project.js` is absent. `scripts/` only holds `seed-auth-users.mjs`, a one-off Node script that creates a Supabase Auth login for every `public.users` row with the same UUID. The Supabase URL and secret key are hard-coded locally in that file, so it is listed in `.gitignore` and must never be committed; only `SEED_PASSWORD` comes from the shell environment. The secret key must never go into the app or `environment.ts`.
- Never leave comments. Code should be self-explanatory.
- Always verify AGENTS.md after doing anything to see if you need to add or remove anything from here.

## App wiring

- `package.json` enters through `expo-router/entry`. `app/index.tsx` redirects to `/(auth)/Welcome`; its Login button opens `/(auth)/Login` and its Register button does nothing yet. `app/(auth)/Login.tsx` has email and password fields built from `components/AuthInput.tsx`, a show/hide password toggle, an inline error line, and a Log in button (`BasicButton` with a `disabled` prop) whose `handleLogin` rejects empty fields, otherwise dispatches the `loginUser` thunk from `store/slices/userSlice.ts` and on success does `router.replace("/(tabs)/FeedPage")`; on failure it shows the rejected message. `loginUser` calls `signInWithEmail` in `actions/auth.ts`: `supabase.auth.signInWithPassword`, then a `users` query by the auth UUID (`users.id` equals the Auth user id), mapped by `utils/userMapper.ts`. If the profile row cannot be read it signs out locally and fails with a profile error; an `AuthApiError` 4xx maps to "Invalid email or password."; anything else maps to a connection error. The `users` table needs the RLS policy `for select to authenticated using (auth.uid() = id)`; anon reads return nothing. The session is kept in memory only (`persistSession: false`), so every launch starts at Welcome; `autoRefreshToken: true` keeps the access token valid so authenticated RPCs keep working past one hour. There is no logout. Its "Register" link is a no-op until a Register page exists. Supabase `signInWithPassword` takes an email, not a username, so the field is email-only. `app/_layout.tsx` loads Silkscreen fonts and wraps all routes in the Redux provider and gesture-handler root. Inside it, `components/CatalogGate.tsx` dispatches `loadCatalog` on launch and shows a spinner until the first load settles; `components/ConnectionBanner.tsx` renders over the routes.
- `app/(tabs)/_layout.tsx` hides the default tab bar and renders `components/Navbar.tsx`; the navbar explicitly routes to Feed, Map, and Profile even though only Feed is declared in the Tabs layout. Standalone screens such as Camera and Quiz live directly under `app/`.
- Roads, places, and quests are fetched from Supabase at launch with `@supabase/supabase-js` (`lib/supabase.ts`). `actions/catalog.ts` `fetchCatalog` runs four parallel queries (`roads` with `road_places`, `places`, `quests` with `quiz_questions`, `badges` ordered by price) with an 8s timeout, and fails on any error or when roads, places, or badges come back empty. `utils/catalogMapper.ts` maps snake_case rows to the `Road`/`Place`/`Quest`/`Badge` types (badge rows via `utils/badgeMapper.ts`): road places are ordered by `position`, a road's quests follow its place order, and a quiz quest uses only its first `quiz_questions` row (sorted by id). The `loadCatalog` thunk in `store/slices/catalogSlice.ts` (`status`, `initialLoadSettled`) is handled by the `roads`, `places`, `quests`, and `badges` slices. Those slices start from `mocks/` (`badges` from `MOCK_STORE_BADGES`), so a failed load leaves the mock data in place and `ConnectionBanner` shows "Cannot connect to the database" with a Retry button. The banner also covers a failed `loadUserBadges` (`user.badgesStatus`) and a failed `loadProgress` (`progress.status`); it only appears after a failure, and Retry re-dispatches whichever of `loadCatalog`, `loadUserBadges`, and `loadProgress` failed. Quests are read with `selectQuestByPlaceId` from `store/slices/questsSlice.ts`. The anon key needs SELECT policies on `roads`, `places`, `road_places`, `quests`, `quiz_questions`, and `badges`; without them Supabase returns empty lists and the whole catalog falls back to mocks.
- User state in `store/slices/userSlice.ts` starts from `mocks/user-mock.ts` until `loginUser` succeeds, which replaces it with the logged-in `public.users` row (`purchasedBadges` reset, `badgesStatus` set to `loading`). `loginUser` then dispatches `loadUserBadges` and `loadProgress` without awaiting them, so neither failure fails login. `actions/badges.ts` `fetchUserBadges` reads `user_badges` with the embedded `badges(*)` (8s timeout) filtered by the user UUID, and the result fills `purchasedBadges`, which `ProfilePage` renders alone (no hard-coded badges). `user_badges` has the RLS policy `user_badges_select_own` (`for select to authenticated using (user_id = auth.uid())`). `StorePage` reads `state.badges`, hides owned ones, and buys through the `purchaseBadge` thunk, which calls the `purchase_badge` RPC (`buyBadge` in `actions/badges.ts`) and sets `coins` from the server result. Coins are never changed locally: every progress and purchase RPC result overwrites `user.coins`.
- Backend progress lives in `user_progress (user_id uuid, road_id, place_id)` (foreign key to `road_places`), `user_roads (user_id, road_id, started_at, completed_at)` (RLS on, no policies), and `users.active_road_id`. All `user_id` columns are `uuid` with foreign keys to `users`. The schema migration and every RPC are in `supabase/progress-sync.sql` (local only, because `.gitignore` ignores `supabase/`; already applied; a `backup` schema holds pre-migration copies of `users`, `user_badges`, `user_progress`, and `leaderboard_entries`). `supabase/reset-user-progress.sql` (also local only) resets one user, set by the UUID in its `v_user` variable: it deletes their `user_progress`, `user_roads`, and `leaderboard_entries` rows and sets `active_road_id = null` and `coins = 0`, keeping `user_badges`. The `SECURITY DEFINER` RPCs bypass RLS and act on `auth.uid()`: `get_my_progress()`, `start_road(p_road_id)`, `leave_road()`, `complete_place(p_road_id, p_place_id)`, and `purchase_badge(p_badge_id)`. Progress RPCs return `{ coins, active_road_id, roads: [{ road_id, completed, place_ids }] }`, and `complete_place` adds `reward` and `road_completed`. `complete_place` only accepts the next unfinished place by `position` on the active road, adds `quests.reward` to `users.coins` and to `leaderboard_entries (track_id = road id)`, and on the last place sets `user_roads.completed_at` and clears `active_road_id`. `start_road` rejects completed roads. Rule failures are raised with code `P0001` and their message is shown to the user.
- `lib/rpc.ts` `callRpc` wraps `supabase.rpc` with an 8s timeout; errors without a code become the connection message. `actions/progress.ts` calls the progress RPCs and `utils/progressMapper.ts` maps them. `store/slices/progressSlice.ts` holds `status`, `activeRoadId`, `roads` (per road `placeIds` and `completed`), `replay`, and `saving`, with the thunks `loadProgress`, `startRoad`, `leaveRoad`, `startReplay`, and `submitPlaceCompletion`, plus the `stopReplay` action. Replay of a completed road is client-only: `startReplay` leaves any active road, and `submitPlaceCompletion` on the replayed road enforces the order locally, pays 0, and is never saved. A failed save shows an alert and records nothing. Ordering helpers (`getNextPlace`, `getPlaceStatus`, `isRoadFinished`, `getRoadReward`, `formatCompletionMessage`) are in `utils/progress.ts`.
- `QuizPage` checks the answer locally, and `CameraPage` always accepts the photo. Both dispatch `submitPlaceCompletion` with the `roadId` and `placeId` route params; there is no photo verification backend.
- The leaderboard is always fetched from the Supabase edge function `get-leaderboard` (`GET ?trackId=<road id>`) by `actions/leaderboard.ts`, through `hooks/useTrackLeaderboard.ts` (React Query; `QueryClientProvider` lives in `app/_layout.tsx`). The function calls the SQL `get_leaderboard(p_track_id)`, which left-joins every user to `leaderboard_entries` for that road. Config is `supabaseUrl` and `supabasePublishableKey` in `environment.ts`. `MOCK_USER.id` is the real `raresc4` UUID so the leaderboard can highlight the current user. `supabase/seed.sql` is out of date (its `user-1` ids are not UUIDs) and must not be run against this schema.
- `app/(tabs)/MapPage.tsx` renders `MapView` and `Marker` from `react-native-maps`; do not assume the map works on web. The current road is `progress.replay?.roadId ?? progress.activeRoadId`; while it is set, the map shows all its places (completed green, next orange, locked gray), only the next place opens `MapPopup`, and `Header` shows a Leave button. With no current road, each road shows its first place (green when completed); tapping a marker expands that road and opens `MapBottomSheet` with Start, Continue, or Replay Track. Marker keys include the variant because `tracksViewChanges={false}` does not redraw color changes. Feed navigation params (`roadId`, `openSheet`) are cleared with `router.setParams` after they are handled. Place, badge, and avatar images are resolved by `resolveImage` in `utils/resolveImage.ts`: `imageUrl` wins, otherwise `imageId` is looked up in its single static `IMAGE_MAP` require table, otherwise the `statuie.png` fallback is used. Add a table entry whenever a new `image_id` appears in the database or mocks.
