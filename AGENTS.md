# Repository notes

- This is a single Expo 57 / Expo Router app (npm lockfile; no workspace). Install with `npm ci`, run with `npm start`; `npm run ios`, `npm run android`, and `npm run web` use the scripts in `package.json`.
- Verification: `npm run lint` (`expo lint`); focus on one file with `npx eslint 'app/(tabs)/MapPage.tsx'`; typecheck with `npx tsc --noEmit`. There is no test script or test suite configured. `npm run lint` already reports errors in `MapPage.tsx` and `Navbar.tsx`. Typed routes live in the generated `.expo/types/router.d.ts`; after adding a route, `tsc` fails on links to it until `npm start` regenerates that file.
- Do **not** run the README's `npm run reset-project`: its target `scripts/reset-project.js` is absent. `scripts/` only holds `seed-auth-users.mjs`, a one-off Node script that creates a Supabase Auth login for every `public.users` row with the same UUID. The Supabase URL and secret key are hard-coded locally in that file, so it is listed in `.gitignore` and must never be committed; only `SEED_PASSWORD` comes from the shell environment. The secret key must never go into the app or `environment.ts`.
- Never leave comments. Code should be self-explanatory.
- Always verify AGENTS.md after doing anything to see if you need to add or remove anything from here.

## App wiring

- `package.json` enters through `expo-router/entry`. `app/index.tsx` redirects to `/(auth)/Welcome`; its Login button opens `/(auth)/Login` and its Register button does nothing yet. `app/(auth)/Login.tsx` has email and password fields built from `components/AuthInput.tsx`, a show/hide password toggle, an inline error line, and a Log in button (`BasicButton` with a `disabled` prop) whose `handleLogin` rejects empty fields, otherwise dispatches the `loginUser` thunk from `store/slices/userSlice.ts` and on success does `router.replace("/(tabs)/FeedPage")`; on failure it shows the rejected message. `loginUser` calls `signInWithEmail` in `actions/auth.ts`: `supabase.auth.signInWithPassword`, then a `users` query by the auth UUID (`users.id` equals the Auth user id), mapped by `utils/userMapper.ts`. If the profile row cannot be read it signs out locally and fails with a profile error; an `AuthApiError` 4xx maps to "Invalid email or password."; anything else maps to a connection error. The `users` table needs the RLS policy `for select to authenticated using (auth.uid() = id)`; anon reads return nothing. The session is kept in memory only (`persistSession: false`, `autoRefreshToken: false`), so every launch starts at Welcome and the access token is not refreshed. There is no logout. Its "Register" link is a no-op until a Register page exists. Supabase `signInWithPassword` takes an email, not a username, so the field is email-only. `app/_layout.tsx` loads Silkscreen fonts and wraps all routes in the Redux provider and gesture-handler root. Inside it, `components/CatalogGate.tsx` dispatches `loadCatalog` on launch and shows a spinner until the first load settles; `components/ConnectionBanner.tsx` renders over the routes.
- `app/(tabs)/_layout.tsx` hides the default tab bar and renders `components/Navbar.tsx`; the navbar explicitly routes to Feed, Map, and Profile even though only Feed is declared in the Tabs layout. Standalone screens such as Camera and Quiz live directly under `app/`.
- Roads, places, and quests are fetched from Supabase at launch with `@supabase/supabase-js` (`lib/supabase.ts`). `actions/catalog.ts` `fetchCatalog` runs four parallel queries (`roads` with `road_places`, `places`, `quests` with `quiz_questions`, `badges` ordered by price) with an 8s timeout, and fails on any error or when roads, places, or badges come back empty. `utils/catalogMapper.ts` maps snake_case rows to the `Road`/`Place`/`Quest`/`Badge` types (badge rows via `utils/badgeMapper.ts`): road places are ordered by `position`, a road's quests follow its place order, and a quiz quest uses only its first `quiz_questions` row (sorted by id). The `loadCatalog` thunk in `store/slices/catalogSlice.ts` (`status`, `initialLoadSettled`) is handled by the `roads`, `places`, `quests`, and `badges` slices. Those slices start from `mocks/` (`badges` from `MOCK_STORE_BADGES`), so a failed load leaves the mock data in place and `ConnectionBanner` shows "Cannot connect to the database" with a Retry button. The banner also covers a failed `loadUserBadges` (`user.badgesStatus`); it only appears after a failure, and Retry re-dispatches whichever of `loadCatalog` and `loadUserBadges` failed. Quests are read with `selectQuestByPlaceId` from `store/slices/questsSlice.ts`. The anon key needs SELECT policies on `roads`, `places`, `road_places`, `quests`, `quiz_questions`, and `badges`; without them Supabase returns empty lists and the whole catalog falls back to mocks.
- User state in `store/slices/userSlice.ts` starts from `mocks/user-mock.ts` until `loginUser` succeeds, which replaces it with the logged-in `public.users` row (`completedPlaces` and `purchasedBadges` reset, `badgesStatus` set to `loading`). `loginUser` then dispatches the `loadUserBadges` thunk without awaiting it, so a badge failure never fails login: `actions/badges.ts` `fetchUserBadges` reads `user_badges` with the embedded `badges(*)` (8s timeout) filtered by the user UUID (`user_badges.user_id` is `text`), and the result fills `purchasedBadges`, which `ProfilePage` renders alone (no hard-coded badges). `user_badges` needs the RLS policy `for select to authenticated using (user_id = auth.uid()::text)`. `StorePage` reads `state.badges` and hides owned ones. `purchaseBadge` only updates Redux; purchases and coin changes are not written to the backend and are lost on the next login. The camera flow is different: `actions/camera.ts` posts photos to `/verify-location` using the hard-coded ngrok `apiUrl` in `environment.ts`. Check that endpoint before relying on photo verification.
- The leaderboard is always fetched from the Supabase edge function `get-leaderboard` (`GET ?trackId=<road id>`) by `actions/leaderboard.ts`, through `hooks/useTrackLeaderboard.ts` (React Query; `QueryClientProvider` lives in `app/_layout.tsx`). Config is `supabaseUrl` and `supabasePublishableKey` in `environment.ts`. Points earned in Camera and Quiz are not written back to the backend. `MOCK_USER.id` is the real `raresc4` UUID so the leaderboard can highlight the current user.
- `app/(tabs)/MapPage.tsx` renders `MapView` and `Marker` from `react-native-maps`; do not assume the map works on web. Place, badge, and avatar images are resolved by `resolveImage` in `utils/resolveImage.ts`: `imageUrl` wins, otherwise `imageId` is looked up in its single static `IMAGE_MAP` require table, otherwise the `statuie.png` fallback is used. Add a table entry whenever a new `image_id` appears in the database or mocks.
